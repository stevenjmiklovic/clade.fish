Installation

#

You’ll need fish 3.6 or newer, jq for snapshots and archives, and tar. Choose your fish package manager.

Optional encryption uses GnuPG for snapshots and sops 3.9 or newer for exports.

fish 
omf install https://github.com/stevenjmiklovic/clade.fish

Open a new shell after installing, or run exec fish. The package is called clade.fish; the command is clade. Upgrade later with omf update clade.fish.

fish 
fisher install stevenjmiklovic/clade.fish

Install with Fisher, then run clade to list your profiles.

Clone the repository and link its files into your fish config. Create the destination folders if they don’t exist.

fish 
git clone https://github.com/stevenjmiklovic/clade.fish.git
cd clade.fish
mkdir -p ~/.config/fish/{functions,completions,conf.d}
for f in functions/*.fish completions/*.fish conf.d/*.fish
    ln -s $PWD/$f ~/.config/fish/$f
end

Your first profile

#

Start with a copy of your stock config. Switch to it, then log in once. Each profile keeps its own Claude Code login.

fish 
# Create ~/.workclaude with your portable config
clade new work --from claude
clade use work
claude

# Use work in new shells, too
clade use -u work

# Run once with the stock profile, without switching
clade run claude -p "hello"
↳

Back to your usual setup? Run clade use claude. To reset the default for new shells, run clade default claude.

Working with profiles

#

A profile is a Claude Code config directory: ~/.claude, or a directory like ~/.workclaude. Each has its own settings, CLAUDE.md, skills, agents, plugins, history, and login.

clade discovers directories matching ~/.*claude. Short names work: work resolves to workclaude. You can also use a path, such as clade use ./sandbox/testclaude.

fish 
clade                  # List profiles; * marks the active one
clade current          # Show this shell’s profile
cd (clade path work)    # Open its config directory
clade default work     # Set the default for new shells

What switching changes

clade use sets CLAUDE_CONFIG_DIR for this shell and the programs it starts. Already running Claude Code sessions keep their current profile. A child shell that inherits this variable keeps the same profile, even if you’ve set a different default.

↳

The stock claude profile is special: clade unsets CLAUDE_CONFIG_DIR so Claude Code uses your existing ~/.claude.json and login.

Snapshots & restore

#

Save a known-good config before changing hooks, skills, or settings. A snapshot is a timestamped archive of your portable config.

fish 
clade snapshot work -m "before plugin cleanup"
clade history work
clade diff work        # Compare with the newest snapshot
clade restore work 2   # Restore the second-newest snapshot
clade restore work 1   # Undo that restore

SNAP can be a number from clade history (1 is newest), or a snapshot ID such as 20260930T185201Z. clade snapshots the current state before restoring. Files created since the saved snapshot stay in place and are listed.

Snapshots live in ~/.local/share/clade/snapshots/<profile>/, or your configured data directory. They keep secrets, use private permissions (600 files in a 700 directory), and are never automatically deleted. You can encrypt new snapshots with GPG.

For scripts, clade diff exits 0 when identical, 1 when changed, and 2 on error.

Export & import

#

Move a setup to another machine, or share it with a teammate. Export writes a self-contained .clade.tar.gz archive and redacts secret-looking environment values by default.

fish 
# On the first machine
clade export work -o work.clade.tar.gz

# On the other machine
clade import work.clade.tar.gz work
clade use work
claude                 # Log in for this profile

What travels with your profile

✓ Portable config

  • settings.json, CLAUDE.md, keybindings.json
  • agents/, commands/, skills/, output-styles/
  • hooks/, rules/, and paths in $clade_include

− Stays on the machine

  • .claude.json, credentials, and logins
  • History, projects, sessions, and todos
  • Caches, logs, file history, shell snapshots, and plugins/

Snapshots and new --from use the same portable config list. Enabled plugins and extra marketplaces travel in settings.json; plugin caches and registries don’t. If plugins are missing after import, run /plugin in Claude Code.

When you import or copy under a new name, clade rewrites references to the old profile directory in settings.json. Exports follow symlinks to make archives self-contained. Imports validate the archive before writing.

Merge into an existing profile

fish 
clade import work.clade.tar.gz work --merge

A merge snapshots the target first, adds and replaces portable files, and leaves all other files in place. Without --merge, import refuses an existing profile.

Inside a clade archive

A gzipped tar contains the portable files and a clade.json manifest with format version, clade version, profile name, source directory, home directory, timestamp, label, and redacted env names. Plain archives use format 1; exports with sops-encrypted secrets use format 2, which clade 0.2 and earlier refuse.

Encryption

#

Use GPG to protect whole snapshot archives, or sops to encrypt secret-looking environment values in an export’s settings.json.

Encrypt snapshots with GPG

fish 
clade encryption on you@example.com  # Or a key ID or fingerprint
clade encryption                     # Check keys and snapshot counts
clade encryption off                 # Stop encrypting new snapshots

Enabling checks that the private key is present and a test encryption and decryption succeeds. Every new snapshot, including automatic backups before restore and merge, is saved as .tar.gz.gpg and checked by decrypting it before it is kept.

history reads labels from a small sidecar file without a passphrase. diff and restore decrypt into a private temporary directory. For terminal pinentry, set set -gx GPG_TTY (tty).

!

Back up your private key somewhere other than this machine. Losing it makes encrypted snapshots unrecoverable. Existing snapshots stay as they are; enabling encryption doesn’t encrypt old ones. Missing keys stop restore and merge before the profile changes.

Encrypt export secrets with sops

Configure recipients with sops environment variables, a .sops.yaml file, or clade_sops_args. For example, replace FINGERPRINT with your recipient’s PGP fingerprint:

fish 
set -U clade_sops_args --pgp FINGERPRINT
clade export work --sops -o work.clade.tar.gz
clade import work.clade.tar.gz work

--sops replaces redaction with encrypted ENC[…] values. Other settings stay readable. Recipients can use PGP, age, AWS KMS, GCP KMS, Azure Key Vault, or Vault; multiple recipients can open the same archive.

clade checks that every matching secret value was encrypted before writing the export. Import needs a recipient key and decrypts before creating or changing a profile. An export with no matching secrets stays plain, in format 1.

Safety & secrets

#

clade keeps a way back when it changes an existing profile. Here’s what to expect:

  • A snapshot before changes. Restore and import with --merge stop if the backup fails.
  • No profile deletion. Restore and merge only add or replace files. New profiles and exports refuse existing destinations.
  • Validated imports. Archives with absolute paths, .., links, special files, or paths outside the portable config list are rejected.
  • Machine state stays put. Credentials, history, sessions, and projects aren’t copied into archives or written over.

Redaction has a specific scope

On export, values in settings.json’s env object are replaced with <redacted by clade> when their names contain KEY, TOKEN, SECRET, PASSW, CREDENTIAL, or BEARER, case-insensitively. Import lists those names so you can fill them in.

!

Review an archive before sharing. Secrets elsewhere, such as inside a hook command, aren’t detected. --include-secrets disables export redaction; --sops encrypts matching values instead. Snapshots retain secret values, and can be protected with GPG.

If settings.json can’t be parsed, export stops.

Command reference

#

Use clade help COMMAND or clade COMMAND -h for built-in help. Optional NAME arguments default to your active profile, except on import, which uses the name in the archive.

clade list [-s]

List profiles. * marks the active profile; -s prints bare names. Running clade alone also lists profiles.

clade use [-u] NAME

Switch this shell to a profile. -u also sets the default for new shells.

clade current

Print the active profile name, or its path if it lives outside your home directory.

clade path [NAME]

Print a profile’s directory. Use cd (clade path work) to open it.

clade default [NAME]

Show or set the profile new shells start with.

clade run NAME [ARGS...]

Run claude once with a profile without switching this shell. All arguments after NAME go to Claude Code.

clade new NAME [--from SRC]

Create ~/.NAMEclaude, optionally copying another profile’s portable config.

clade snapshot [NAME] [-m MSG]

Save portable config as a snapshot with an optional message.

clade history [NAME]

List snapshots, newest first, with their number, ID, size, and label.

clade diff [NAME] [SNAP]

Compare a saved snapshot with the current config. SNAP defaults to 1, the newest.

clade restore NAME [SNAP]

Restore a snapshot, saving the current state first. Newer files stay in place.

clade encryption [status | on KEY... | off]

Show encryption status, enable GPG encryption of new snapshots, or turn it off. Keys must have an available private key and pass an encryption and decryption check.

clade export [NAME] [-o FILE] [--sops | --include-secrets]

Export config to an archive. The default filename is NAME-YYYYMMDD.clade.tar.gz. Secret-looking env values are redacted by default, encrypted with --sops, or kept with --include-secrets.

clade import FILE [NAME] [--merge]

Import an archive into a new profile, or merge into an existing one. NAME defaults to the name in the archive.

clade help [COMMAND]

Show general help or help for one command. -h and --help work too.

clade version

Print the installed clade version. Also available as -v or --version.

Aliases: ls for list and log for history.

Configuration

#

Configure clade with fish variables. Use set -U when you want a value to persist across shells.

VariableDefault & purpose
clade_defaultUnset (stock claude). The default for new shells; set it with clade default.
clade_data_dir$XDG_DATA_HOME/clade or ~/.local/share/clade. Snapshot storage.
clade_includeNone. Extra paths inside a profile to include as portable config.
clade_secret_patternKEY|TOKEN|SECRET|PASSW|CREDENTIAL|BEARER. Case-insensitive regex for env names redacted or encrypted on export.
clade_gpg_recipientsUnset. GPG fingerprints for new snapshots. Set with clade encryption on.
clade_sops_argsNone. Extra sops encrypt flags, such as --pgp FINGERPRINT or --age RECIPIENT.
fish 
set -U clade_include statusline.sh

Put your profile in your prompt

#

With Starship, add this to your starship.toml:

toml 
[env_var.CLAUDE_CONFIG_DIR]
format = "[✻ $env_value]($style) "
style = "yellow"

In a fish prompt, use clade current. Check set -q CLAUDE_CONFIG_DIR to show a profile indicator only when using a non-stock profile.

Uninstall

#
fish 
omf remove clade.fish
# Or, with Fisher:
fisher remove stevenjmiklovic/clade.fish

Uninstalling removes the saved default. Your profiles and snapshots stay where they are.
